# מערכת תיאום הנדסי

מעקב בקשות לתיאום תכנון, אישור לביצוע עבודה ואישור גמר עבודה; גורמי תשתית, משימות, מסמכים (מקובצים לפי מספר בקשה), ודוחות וגרפים. בקשות נפתחות רק מ"הגשת בקשה" במסך הכניסה.

**ברירת מחדל:** ערכת אוקיינוס, רקע זוהר נע, כרטיסי זכוכית, פינות מעוגלות ותפריט צד צף. משתמש שכבר שמר עיצוב משלו ממשיך לראות את שלו.

**עיצוב:** 7 ערכות מוכנות, 7 ערכות צבעים (כולל כהות), צבע הדגשה אישי עם תיקון ניגודיות אוטומטי, רקעים (גרדיאנט, זוהר נע, נייר שרטוט), כרטיסי זכוכית/מוגבהים/קו מתאר, רוחב תוכן, תפריט צף, גופנים וגודל טקסט, ניגודיות גבוהה. ההעדפות נשמרות לכל משתמש בשרת.

**גרפים:** עמידה בזמני טיפול, מגמת בקשות לפי חודש, חלוקה לפי סוג וסטטוס, החלטות גורמי תשתית ומשימות. לכל גרף: טולטיפ בעכבר ובמקלדת, תצוגת טבלה, ייצוא CSV והדפסה. ללא ספריות חיצוניות. עברית RTL, ללא תלויות חיצוניות (Node.js 22.16 ומעלה בלבד).

## הפעלה
```bash
cp .env.example .env          # מלאו PUBLIC_URL ושאר הערכים
node create-admin.js   # יצירת מנהל ראשון (או ADMIN_USERNAME/ADMIN_PASSWORD ב-.env)
npm start                      # מפעיל את start.js: שחזור מהענן ← שרת
```
בפרודקשן השרת מצפה ל-HTTPS: הציבו אותו מאחורי Nginx/Load Balancer עם תעודת TLS, והגדירו `TRUST_PROXY=1`.

## הגשת בקשה מהציבור (תושבים ויזמים)
- במסך הכניסה יש כפתור "הגשת בקשה". הפונה בוחר תושב/ת או יזם, ממלא שם משתמש (אפשר בעברית), סיסמה, סוג בקשה, אימייל, כתובת, פלאפון ופרויקט, ומצרף תוכנית תוואי (PDF/DWF בלבד) ובקשת עבודה (PDF, Word או תמונה). חובה גם למלא את טופס "משטרה".
- אחרי השליחה נפתח לו משתמש, הוא מחובר אוטומטית ומקבל את מספר הבקשה על המסך ובאימייל.
- טופס המשטרה הופך אוטומטית ל-PDF שמצורף לבקשה, וגלוי רק למנהל המערכת ולאחראי מיפוי בקשות (הוא כולל ת.ז או ח.פ).
- מנהל המערכת וכל משתמש שסומן "אחראי מיפוי בקשות" (בעריכת משתמש) מקבלים הודעה ואימייל על כל בקשה חדשה, ובוחרים את גורמי התשתית ואת סדר הטיפול.
- הגדרות → סוגי בקשות: לכל סוג – מטפלים אוטומטיים, גורמי תשתית בסדר קבוע, וקבוצת הרשאות לתושבים וליזמים (התפקידים "תושב/ת" ו"יזם" נוצרים מראש ונערכים בתפקידים והרשאות). אפשר לסגור את ההגשה מהציבור בהגדרות וקבצים.
- הגנות: שדה מלכודת לבוטים, עד 5 הגשות בשעה מאותו מחשב, בדיקת תוכן הקבצים, בדיקת ספרת ביקורת של ת.ז, ותפקיד ציבורי לא יכול לקבל הרשאות ניהול או צפייה בכל הבקשות.

## מיקום העבודה (GovMap)
- בטופס "הגשת בקשה", מתחת לפרויקט, יש שדה חובה "מיקום". הוא פותח את מפת GovMap ממורכזת על קריית גת (עם חיפוש רחוב). המגיש לוחץ על המקום המדויק ושומר.
- המיקום נשמר בבקשה (קואורדינטות רשת ישראל) ומוצג לכל מי שמטפל בבקשה, בכל שלב, כמפה עם סמן ליד פרטי הבקשה, עם כפתור "פתיחה ב-GovMap". הוא מופיע גם במסמך האישור. אחראי מיפוי ומי שמורשה לערוך יכולים לעדכן אותו.
- **המפה דורשת מפתח (טוקן) של GovMap** שמונפק לכתובת האתר: מבקשים אותו בשירות "בקשה לקבל או לחדש טוקן" באתר gov.il, ומזינים אותו בהגדרות וקבצים → מפת GovMap (או במשתנה `GOVMAP_TOKEN`). עד שיש מפתח, המגיש פותח את GovMap בלשונית נפרדת ומדביק את הקישור, והמערכת קוראת ממנו את המיקום.
- אבטחה: רק עמוד המפה (`map.html`) רשאי לטעון את GovMap, ורק בתוך האתר עצמו. שאר המערכת נשארת חסומה לסקריפטים חיצוניים.

## רשימת הבקשות ומסמכים
- כל הבקשות: לשוניות "בקשות פתוחות" ו"בקשות שטופלו" (אושרה / נדחתה). החיפוש והסינון לפי סטטוס וסוג פועלים מיד, בלי כפתור, ובשתי הלשוניות.
- מסמכים: בתפריט הצד "מסמכים" היא תיקייה שנפתחת ונסגרת, ובתוכה "בקשות פתוחות" ו"בקשות שטופלו". במסך עצמו כל בקשה היא תיקייה, לפי מספר הבקשה.
- החזרה לתיקון: בוחרים למי מחזירים – למגיש או לגורם תשתית מסוים. מי שנבחר מקבל התראה ואימייל עם סיבת ההחזרה וקישור לבקשה. החזרה לגורם פותחת מחדש את חוות הדעת שלו, והתור חוזר אליו. כשמנהל המערכת מחזיר לגורם בשלב האישור הסופי, אחרי שהגורם מתקן ומאשר הבקשה מאושרת אוטומטית ומסמך האישור נשלח למגיש, בלי בדיקה חוזרת. אפשר לבטל את זה בחלון ההחזרה.
- מסך הכניסה: הכותרת והתיאור בצד נערכים בהגדרות וקבצים → מסך הכניסה.

## סדר טיפול, אישור סופי ומסמכים
- הגורמים מטפלים בבקשה לפי הסדר שנקבע. כל גורם מקבל הודעה ואימייל רק כשהקודם סיים (אישר או אישר בתנאים). דחייה עוצרת את הבקשה ומודיעה למטפל.
- כשכל הגורמים מאשרים, הבקשה עוברת ל"ממתינה לאישור מנהל המערכת". האישור של מנהל המערכת מסיים את הבקשה (אין שלב סגירה נפרד), ומפיק אוטומטית מסמך "אישור לביצוע עבודה" (PDF עם הלוגו, פרטי הבקשה, הגורמים המאשרים וההנחיות). המסמך נשלח למגיש באימייל ומופיע בעמוד הבקשה. את ההנחיות במסמך עורכים בהגדרות וקבצים → מסמך האישור.
- מסמכים: כברירת מחדל כל משתמש רואה רק את המסמכים שהעלה, ומנהל המערכת רואה הכל. ניתן לשנות בהגדרות וקבצים → "מי רואה מסמכים".
- משתמש חדש: תפקיד, גורם תשתית ושיוך לבקשה הם שדות חובה (עם אפשרות מפורשת "לא משויך" / "ללא שיוך לבקשה").

## זכור אותי
במסך הכניסה. עם הסימון – מחובר עד 30 יום (פג אחרי 7 ימים בלי שימוש). בלי הסימון – הסשן נמחק כשסוגרים את הדפדפן, ופג אחרי 30 דקות בלי שימוש. ניתן לשנות ב-`.env`: `REMEMBER_DAYS`, `REMEMBER_IDLE_DAYS`.

## לוגו, מספור בקשות וגורמי תשתית
- לוגו: הגדרות וקבצים → לוגו (PNG/JPG/WebP עד 1MB). מופיע במסך הכניסה ובתפריט.
- מספור בקשות: הגדרות וקבצים → מספור בקשות (קידומת, שנה, ספרות, המספר הבא). מספר של בקשה קיימת משנים מעמוד הבקשה.
- גורמי תשתית: תפקידים והרשאות → לשונית "גורמי תשתית" (הוספה, עריכה, שיוך משתמשים, השבתה ומחיקה).

## דוא"ל
לשליחת אימיילים (בקשה חדשה, תור של גורם, מסמך האישור, איפוס סיסמה) מלאו `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` ב-`.env`. בלי זה בקשות איפוס מגיעות כהתראה למנהל.

## אחרי שינוי ב-app.js או app.css
```bash
npm run build   # יוצר app.min.js / app.min.css. אם הם ישנים מהמקור, השרת מגיש את המקור.
```

## שמירת הנתונים בענן (Render בחינם ודומיו)
באחסון שהדיסק שלו נמחק בכל הפעלה מחדש, מגדירים סנכרון ל-Supabase Storage (חינם עד 1GB):
1. ב-supabase.com: פרויקט חדש ← Storage ← New bucket בשם `handasa`, **פרטי** (לא Public).
2. Project Settings ← API Keys: מעתיקים את ה-Project URL ואת מפתח ה-secret (או service_role).
3. ב-Render ← Environment: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPABASE_BUCKET=handasa`. ‏Start Command: `npm start`.
המערכת משחזרת את המסד בכל הפעלה, שומרת אותו לענן כמה שניות אחרי כל שינוי (ועותק יומי ב-`db/daily/`), והקבצים עולים לענן מיד. אם הענן לא זמין בהפעלה – השרת לא דורס את העותק השמור.
המפתח נשאר בשרת בלבד ולא נשלח לדפדפן.

## אפליקציה
המערכת ניתנת להתקנה (PWA): Android ומחשב (Chrome/Edge) – כפתור התקנה קטן בפס העליון ובמסך הכניסה; iPhone/iPad ו-Safari במק – הכפתור מציג הוראות. אחרי ההתקנה הכפתור לא מוצג.

## גיבוי
גיבוי אוטומטי של המסד והקבצים כל `BACKUP_INTERVAL_MINUTES` (ברירת מחדל 60), שמירה 30 יום. כדי שהגיבוי יהיה מחוץ לשרת, הפנו את `BACKUP_DIR` לדיסק ענן מעוגן (S3/Azure Blob דרך mount, תיקייה מסונכרנת וכו').

## מבנה
כל הקבצים יושבים בתיקייה אחת, בלי תתי-תיקיות. מעלים את כולם כמו שהם לאותה תיקייה בשרת.

- `start.js` – נקודת ההפעלה (שחזור מהענן, ואז השרת)
- `cloudsync.js` – סנכרון לענן
- `sw.js`, `manifest.webmanifest`, `icon-*.png`, `logo.png` – אפליקציה, אייקונים ולוגו ברירת מחדל
- `server.js` – השרת: HTTPS, CORS, CSRF, rate limit, כותרות אבטחה
- `routes.js` – כל ה-API ובדיקות ההרשאה
- `permissions.js` – קטלוג 26 ההרשאות ותפקידי ברירת המחדל
- `uploads.js`, `auth.js`, `security.js`, `db.js`, `backup.js`, `mailer.js`, `config.js`, `workflow.js` – מודולי השרת
- `index.html`, `app.js`, `app.css` (+ `.min`), `privacy.html`, `accessibility.html`, `404.html` – ממשק המשתמש
- `create-admin.js`, `build.js`, `scan-secrets.js` – כלי ניהול; `security.test.js`, `browser.test.js` – בדיקות

השרת מגיש לדפדפן **רק** את הקבצים הציבוריים שברשימה ב-`server.js`. קוד השרת, `.env`, מסד הנתונים והבדיקות לא נגישים מהרשת, למרות שהם באותה תיקייה.

תיקיית `data` (מסד נתונים, קבצים מצורפים, גיבויים ולוגים) **נוצרת אוטומטית** בהפעלה הראשונה – אין צורך להעלות אותה.
